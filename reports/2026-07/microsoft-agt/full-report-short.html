微软在 AI Agent 安全治理方向推出了重量级开源项目 agent-governance-toolkit（简称 AGT），5,181 星，46/天稳定增长。本文从 RebornClaw 的视角做深度竞品分析，重点回答：哪些值得借鉴，哪些我们已经在做了，哪些我们不需要做？

一、AGT 核心架构

AGT 的核心理念：Prompt-level safety is not a control surface. It is a polite request to a stochastic system.

翻译：在提示词层面做安全控制不是控制面，只是对随机系统的一个礼貌请求。

AGT 不做"请模型遵守规则"，而是在确定性代码层拦截每次工具调用、消息发送和委托，在模型意图到达网络之前做策略裁决。

四、哪些值得借鉴

✅ 优先级 1 — 直接借鉴
  1. 策略引擎 — YAML 策略文件 + 条件评估。核心思路跟我们的"审计 Agent 规则引擎"一致，但更完整。可以直接用类似设计，不用重新发明轮子
  2. 熔断器 — 简单但有效，连续失败 N 次后断路。几行代码就能落地
  3. Tool Wrapper（工具包装器） — 每个工具调用被拦截后做策略检查。我们的 Vision Parser / Code Generator 应该统一加这个层
🟡 优先级 2 — 对齐思路
  1. 哈希链审计日志 — 我们已用 JSON 签名做审计，理念一致。AGT 的 hash-chain 更简洁，可考虑对齐
  2. OWASP 合规评估 — 不需要自己造框架，直接用 AGT 的 OWASP 映射表做自评
  3. 执行沙箱 — 四层权限环对于当前阶段太复杂，但 "权限分级" 的思路可以借鉴
🔴 优先级 3 — 暂不需要
  1. 多语言 SDK — 我们 Node.js 为主，当前不需要 Rust/Go 支持
  2. RL 训练治理 — 我们没有 RL 训练场景
  3. 物理 AI 安全 — AGT 为机器人/无人机设计的物理安全层，我们不涉及
  4. Claude Code 集成 — 我们不是 Claude Code 用户

五、AGT 的缺口

⚠️ AGT 没做好的 3 件事
  1. No SBOM — 供应链安全只做 partial，没有 SBOM 生成
  2. No memory sandbox — ASI06 记忆投毒只做 partial，没有内存沙箱或上下文完整性校验
  3. No UI-level guardrails — 没有"人肉确认"的工作流，高风险操作缺少审批界面

有意思的是，第三点（记忆投毒）正是我们 MemChain 研究的核心方向。 AGT 自己承认："No dedicated memory-sandbox or context-integrity module." 而我们的 MemChain "证据计划 → 证据链 → 精简上下文"三层架构，正是解决这个问题的方案。

六、总结：我们该怎么做

📌 对 RebornClaw 的行动建议
  1. 短平快（本周）：给 CS Swarm Server 加熔断器 + Tool Wrapper。这俩是成本最低的"安全基本面"
  2. 中期（2-4 周）：引入 YAML 策略引擎，对齐 AGT 的 PolicyEngine 设计。不需要重写，参考设计即可
  3. 差异化（MemChain 优势）：AGT 的 ASI06 记忆投毒是 Partial，我们用 MemChain 三层架构卡位——这是我们的机会
  4. 不需要做的：多语言 SDK、RL 治理、物理 AI 安全。这些是 AGT 为大企业设计的，我们当前阶段不需要
💡
一句话总结：AGT 验证了我们的方向，特别是审计 Agent + 归因链信任体系。我们的差异化在于 MemChain 记忆层——这是 AGT 承认的缺口，也是我们的机会。
